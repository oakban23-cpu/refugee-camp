# REFUGEE: รายงานวิเคราะห์ประสิทธิภาพ (ขั้น 0–4) · 23 พ.ย. 2026

> ทุกตัวเลขในรายงานนี้มาจากไฟล์ผลการวัดในโฟลเดอร์ `dev/perf/`:
> - `baseline.json`: t_perf.py สถานการณ์ S1–S8, 3 โปรไฟล์ × 2 โหมดคุณภาพ
> - `profile_full.json`: CPU profile ผ่าน CDP
> - `overdraw_base.json`: พิกเซลที่ระบายต่อเฟรม
>
> **สภาพแวดล้อม:** Chromium headless **ไม่มี GPU** (ระบายพิกเซลด้วย CPU), เครื่อง 2 คอร์, P1/P2 บีบ CPU ×4 ผ่าน CDP
> - ตัวเลขเวลาจึงช้ากว่ามือถือจริงมาก ให้ใช้**เทียบก่อน-หลังในสภาพเดียวกัน**เท่านั้น
> - งานระบายพิกเซลเต็มจอดูแพงกว่าจริง เพราะบนมือถือมีการ์ดจอทำแทน แต่ยังเป็นตัวแทนภาระการ์ดจอ แบต และความร้อนได้
> - ระหว่างวัดตรึง `GQ`, `LOWQ`, `FQ.avg` และ `HD2/BXM/OL.fq` ไว้ เพื่อไม่ให้ระบบปรับคุณภาพอัตโนมัติทำให้ผลเพี้ยน

## ขั้น 2–4: ปัญหาที่ยืนยันแล้ว (เรียงตาม ผลได้ ÷ ความเสี่ยง)

### PERF-01 · หน้าเริ่มเกมวาดโลกเกมที่มองไม่เห็นเต็มอัตราทุกเฟรม · ความเสี่ยงต่ำ
- **หลักฐาน:**
  - ทาโลกเกมเป็นสีม่วงบานเย็นแล้วถ่ายจอหน้าเริ่มเกม พบพิกเซลม่วง **0%** (`probe/title_b.png`)
  - แต่ `draw()` ใช้เวลา 283 ms/เฟรม (P2 full) และระบาย 16.5 + 9.4 เท่าของจอต่อเฟรม
  - เครื่องมือ HD-2D (`hd2Warp`/`hd2Pass` 23% ของ CPU), ค่าย, ฉากเลือกอาชีพ ทำงานอยู่ข้างหลังหมด
  - fps หน้าเริ่มเกมจึงต่ำสุดในทุกสถานการณ์ (1.3 fps)
- **ทางแก้:** ข้าม `draw()` เมื่อ `#ttl` แสดงอยู่และยังไม่ `.out` แล้วกลับมาวาดทันทีตอนเริ่มเฟดออก
- **ผลที่คาด:** งานวาดของ canvas หลักตอนอยู่หน้าเริ่มเกมเป็น 0 (ภาพเหมือนเดิม 100%) ลดแบตและความร้อนในช่วงที่ผู้เล่นค้างอยู่หน้าแรก
- **ตรวจหลังแก้:** visual diff หน้าเริ่มเกมต้องเท่าเดิม, fps หน้าเริ่มเกม, เทสหน้าเริ่มเกม/หน้าเลือกอาชีพ (t_v644, t_v649)

### PERF-02 · atlas ของนครอัสตราถูกเก็บซ้ำเป็น canvas (17.9 MB) · ความเสี่ยงต่ำมาก
- **หลักฐาน:**
  - `astCv` (เพิ่มใน v653) เก็บสำเนา canvas ของ atlas 4 ภาพ รวม 17.9 MB และค้างตลอดเกม
  - การวัดตอนทำ v653 แสดงว่า**ไม่ช่วยความเร็วเลย** (ก่อน/หลังเท่ากัน)
- **ทางแก้:** ใช้ภาพตรง ๆ เหมือนเดิม
- **ผลที่คาด:** หน่วยความจำ −17.9 MB

### PERF-03 · แคชของแมพค้างหลังออกจากแมพ (รวมราว 75 MB) · ความเสี่ยงต่ำ-กลาง
- **หลักฐาน (`t_canvas.py`):** หลังเล่นแมพ 9, 44, 38, 40, 2 แล้วกลับค่าย ยังค้างอยู่
  - พื้นอัสตรา 2340² **20.9 MB**
  - กำแพงอัสตรา **11.5 MB**
  - เอฟเฟกต์กลางวันอัสตรา 4.2 + 2.1 MB
  - หมอกแมพใต้ดิน 9.3 MB
  - สไปรต์ลำต้นยักษ์ 5.2 MB
- **ทางแก้:** คืนแคชเหล่านี้เมื่อออกจากแมพไปแล้วเกิน 60 วินาที (กันกรณีวาร์ปไปกลับถี่ ๆ)
- **ต้นทุน:** สร้างใหม่ตอนกลับเข้าเมือง 250 ms ครั้งเดียว (วัดแล้ว: พื้น 191 ms, กำแพง 63 ms) ตกอยู่ในจังหวะหน้าจอโหลดแมพ เท่ากับตอนเข้าเมืองครั้งแรกในปัจจุบัน
- **ผลที่คาด:** หน่วยความจำ −40 ถึง −55 MB ขณะอยู่นอกแมพเหล่านั้น ลดโอกาสที่มือถือแรมน้อยจะปิดแท็บหรือกระตุกเพราะแรมตึง

### PERF-04 · canvas ของหน้าเริ่มเกมและฉากเปิดเรื่องค้างหลังใช้เสร็จ (11.6 MB) · ความเสี่ยงต่ำ
- **หลักฐาน:** `tt3Start` 1830×824 และ `prologueStart` 1830×824 ยังมีชีวิตอยู่ระหว่างเล่น
- **ทางแก้:** ย่อ canvas เหลือ 0×0 และถอดออกจากหน้าเมื่อหน้านั้นจบ
- **ผลที่คาด:** −11.6 MB

### PERF-05 · การเตรียมเสียงดนตรีล่วงหน้าทำงานเป็นก้อนละ 6.7 ms บน main thread · ความเสี่ยงต่ำ
- **หลักฐาน:** จับเวลา callback ของ setInterval ทุกตัว พบ `rkWarm` (บรรทัด 10475 ทุก 700 ms) ใช้เวลา **101 ms ใน 10 วินาที (6.7 ms/ครั้ง)** สูงสุดในบรรดา timer ทั้งหมด ทำให้เฟรมสะดุดเป็นจังหวะช่วงแรกหลังเปิดเพลง
- **ทางแก้:** ย้ายไปทำตอนเครื่องว่าง (`requestIdleCallback` และเช็กเวลาที่เหลือก่อนทำ)
- **ผลที่คาด:** เสียงเหมือนเดิม ไม่มีเฟรมสะดุด 6.7 ms ทุก 0.7 วินาที

### PERF-06 · วาดโลกเกมเต็มอัตราตอนเปิดหน้าต่างเมนู · ⚠ มีผลต่อภาพ (ต้องขออนุญาต)
- **หลักฐาน:**
  - ตอนเปิดหน้าต่าง ยังเห็นโลกข้างหลัง 16–74% (มืดลงใต้ฉากหลังของหน้าต่าง) จึงหยุดวาดไม่ได้
  - แต่เปิดหน้าต่างอุปกรณ์ค้างไว้ยังวาดโลก 246 ms/เฟรม (P2 full)
  - DOM 14,461 โหนด
- **ทางแก้ที่เสนอ:** วาดโลกข้างหลังที่ 15–20 fps ขณะหน้าต่างเปิด (UI ยังลื่นเท่าเดิม)
- **ข้อแลก:** อนิเมชันข้างหลังหน้าต่างจะกระตุกขึ้นเล็กน้อย
- **ผลที่คาด:** CPU/GPU ตอนอยู่ในเมนูลดลงราว 66–75%

### PERF-07 · ฉากต่อสู้ระบายพิกเซล 14 + 3.8 เท่าของจอต่อเฟรม · ต้องวิเคราะห์ต่อ
- **ส่วนประกอบหลัก (เท่าของจอ):**
  - สภาพอากาศ `vzWxDraw` 3.0
  - rim light `gxRimPass` 3.3 (คอมโพสิตบน offscreen ต่อมอนทีละตัว)
  - `mxPrevDraw` 1.1
  - `gxAtmo` 1.0
  - `mxGrade` 1.0
  - vignette 0.93
- **ทางที่เป็นไปได้:**
  - ทำ rim light ที่ครึ่งความละเอียด หรือแคชผลตามเฟรมสไปรต์
  - รวม overlay เต็มจอที่ไม่ขยับเป็นชั้นเดียว
- ต้องทำ visual diff ละเอียด จึงเสนอเป็นรอบถัดไป

### PERF-08 · หน้าผาใต้เกาะอัสตรา 4.9 ms ต่อเฟรม (บนเครื่องไม่มี GPU) · ลำดับต่ำ
- ภาพ 1536×1011 ย่อ/ขยายทุกเฟรม บนมือถือที่มีการ์ดจอถูกกว่านี้มาก
- จะแก้เมื่อพบว่าช้าบนเครื่องจริงเท่านั้น

### PERF-09 · setInterval ถาวร 102 ตัว (24 ms/วินาที, 2.4% CPU) · ลำดับต่ำ
- ไม่มีตัวไหนแพงนอกจาก PERF-05
- การรวม timer เสี่ยงต่อพฤติกรรมเกม จึงไม่แนะนำในตอนนี้

### ตรวจแล้ว ไม่พบปัญหา
- ไม่มี memory leak ของ JS heap
- GC ไม่ทำให้กระตุก
- ไม่มีการโหลดภาพใหญ่ซ้ำ
- WebSocket ไม่หนัก
- listener มีเพดาน

## บทเรียนวิธีวัด (สำหรับรอบหน้า)
- **CPU profile:** กำหนดเวลาระบายพิกเซลให้ "จุด flush" ไม่ใช่ฟังก์ชันที่สั่งวาด
